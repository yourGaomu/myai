## 背景

上一阶段让 Mobile 能看到 MCP 服务状态与工具详情，但遇到 `short_links` 这类「主机已配置、还没批准」的 HTTP 服务，仍需进服务器执行 CLI。此次只补齐 **指定管理员设备在 Mobile 审阅并批准已有 HTTP MCP 声明**。不从手机新增或修改配置、不提交密钥、不开放 stdio 审批、不改 Skill 的存储或导入流程。Agent 必须在线；如果必需服务在启动时因未批准而阻止 Agent 上线，仍走现有 CLI。

## 落地

1. **一次性绑定管理员设备，普通配对保持只读。** 增加主机侧 `myai trust mcp mobile-admin grant|list|revoke`，按现有配对管理中显示的完整授权 ID 操作，不按设备昵称猜测。授权存放在 Agent OS 用户配置目录的独立文件中，绑定当前 Agent 的用户／设备、工作区和这一次配对，仅授予审阅和批准现有 HTTP 声明的权限。复用 `core/trust/trust.go` 的用户目录路径、锁和原子写入模式；不把授权放进工作区 YAML，也不改 Relay 的配对数据库结构。每次审阅或批准都重新检查本地授权；撤销配对或重新配对后，原授权不能使用。授予管理权和撤销管理权不改变已有 MCP 信任记录。
2. **Relay 与 Agent 同时校验。** 在 `core/remote/protocol` 新增专用能力查询、审阅和批准消息。Relay 校验现有配对凭据，从验证结果生成只在 Relay→Agent 使用的配对身份，不从 Mobile 接受角色、配对 ID 或内部消息，不向 Agent 转发原客户端 token。复用 `core/remote/relay/mcp_detail.go` 的限时、原始 socket 和私有请求 ID 路由。Agent 按配对身份校验本地管理授权；批准排队后，在写入前使用现有 Agent→Relay 身份认证（`core/remote/relay/security.go`）调用仅 Agent 可用的窄校验接口，确认该配对及请求仍有效，失败时拒绝。管理链路要求加密传输，本地回环测试除外；拒绝跟随校验请求的重定向。旧 Agent、旧 Relay、离线或权限不足时，都不会启用手机审批入口。既有只读目录和 `mcp_reload` 兼容行为不变，重载本身不授予信任。
3. **审阅有效配置，不拿已加载目录当配置。** 在 `core/App.go`、`core/mcp/config.go` 复用 `LoadMCP`、`Mapper.MCPConfig` 和 `TrustRequest`，读取 Agent 当下的有效配置，包括环境注入的 `short_links`。新增管理员视图，能看到还没有进入已加载目录的声明。仅允许名称唯一、未禁用且无启动命令的 HTTP(S) 声明。返回有界的审阅摘要：服务名、实际目标、权限类别和认证概况。只显示可安全审阅的端点；主机管理员须明确指定允许展示的非敏感路径，带查询参数或不能安全完整确认目标的声明继续走 CLI。不展开请求头的实际值，不返回原始 YAML、环境值、原始错误或声明指纹；审阅不连接上游，也不执行工具。
4. **批准只写信任，不触发加载。** 在 `core/remote/agent/catalog_handlers.go` 的管理队列中处理 `{server_name, review_id}`。短时、一次性的审阅凭据绑定创建时的配对、连接、工作区、服务名和完整指纹；执行前按当前配置重算指纹，并再校验授权。声明改名、移除、禁用、歧义、变更或审阅过期时一律不写，要求重新审阅。复用与 CLI 相同的 `Store.Approve`；已批准的同一声明返回当前状态，不重复写，重复提交不能扩大权限。与 `ReloadMCP` 分开：批准回执只表示已保存；用户主动重载后，只有当前声明实际发布成功才标为「已加载」。如果候选重载失败，保留原运行时；同名旧版本还在时明确显示「旧配置仍在运行」。
5. **Mobile 支持审阅、显式确认和结果恢复。** 在 `mobile/src/components/settings/sections/MCPCatalogSection.tsx` 加「审批 HTTP 服务」入口，单独显示当前声明的信任状态和实际运行状态。复用 `ConfirmModal.tsx`，在确认页展示实际目标；管理请求与现有 `useMCPState.ts` 的目录、重载请求分开追踪，结果绑定配对、连接、请求 ID 和服务。断线、超时或回执未收到时显示「审批结果未确认」，重新查询权威状态，不自动重发、不自动重载。文档补充如何给指定设备授权、撤销，以及必须回到 CLI 的场景。

## 验证

- **权限与路由：** 本地配对集成覆盖普通配对不能审阅或批准、管理员仅可操作指定 Agent／工作区、配对过期或撤销、已排队操作在写入检查前被撤权、伪造身份、重复请求、替换连接和新旧版本混跑。验证不可用时不会降级为信任客户端输入。
- **配置与信任：** 使用本地 HTTP MCP fixture 覆盖 `short_links` 的环境注入和 YAML 优先级、审阅后声明修改、重放、禁用、stdio、带密钥端点与批准后的重载失败。断言审阅和批准不请求上游、不调用工具；CLI 和 Mobile 使用同一指纹与信任记录，仅批准精确声明。验证加载失败时旧目录保持不变。
- **Mobile：** 扩展 `relay-recovery.test.cjs`，覆盖取消、双击、断线后按状态恢复及窄屏操作；运行完整 Go 测试、Mobile 类型检查及脚本测试。仅用本地 fixture，不动生产配置、不推送或部署。
