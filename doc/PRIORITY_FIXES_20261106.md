## 2. 重要行为变化

### 2.1 权限与用户批准

- `PermissionUnknown` 不再等同于只读。未声明能力的 MCP、插件默认 execute；无效声明被拒绝。
- `share_file` 属于对外发布，需要逐次确认；即使 full 模式也不能绕过发布确认或敏感路径拒绝。
- 内置子代理不再自行获得高于父会话的能力。`PermissionCeiling` 的 nil 表示未增设上限，非 nil 空集合表示禁用全部工具；持久化与复制保留这一区别。
- 使用新的 `myai trust hook|plugin|mcp list|approve|revoke` 审阅执行声明。批准绑定工作区、路径和完整摘要；工作区不能通过配置给自己授信。改变声明需要重新审阅。
- Hook 执行前复核批准；插件和 MCP 在加载、启动、重载时检查。独立 CLI 撤销不会跨进程立即杀掉已有运行时，需要重载或重启使撤销对其生效。
- 信任库更新使用稳定 lockfile 的跨进程锁，避免并发批准恢复刚撤销的记录。

### 2.2 Plan 与持久化

- 同一会话中的 Plan 步骤暂时顺序执行。独立子会话和合并所有权完成前，不恢复共享 transcript 的并行写入。
- 自动识别出实现请求后默认生成可保存的草稿，等待用户确认再执行。
- `GetSession`、`Current` 返回深拷贝；写入走 Store 的追加、设置及 CAS 方法，调用者不能依赖修改返回指针生效。
- 失败的异步持久化在进程内保留于队列，等待后续提交或 `Flush` 重试；它尚未落成磁盘 outbox，硬崩溃仍有未落库窗口。同步事务在未执行时取消或因队首失败而作废，不允许回滚内存后再次延迟提交。
- 计划状态使用预期 ID 和 revision 做原子检查。消息、用量与标题更新不能覆盖计划、模式或用户设置。
- 冷加载到 running Plan 或含 running 步骤的计划时，不因“继续”自动重放；需要先核对已发生的工具结果并明确处理状态。已完成计划重载后拒绝再次执行。

### 2.3 模型与上下文

模型默认总请求截止为 10 分钟、流空闲超时为 90 秒、最多 3 次尝试；退避起始 250ms，上限 30 秒。更早的调用方截止优先；收到流式数据后不盲目重放。

模型容量使用 `context_window_tokens` 和 `max_output_limit` 明确配置，不按模型名称猜测。会话窗口 0 表示自动；显式设置只能减小已知模型容量。模型元数据未知时使用保守的 16K 预算。

摘要批输入上限调整为 6000 token，输出上限 2048 token；单次最多 20 批。工具原文取首尾并标注省略量，避免一次大读取引发无界串行摘要调用。预算不足会报告错误并保留已执行工具的证据。

`read_file` 的 `offset`、`limit` 按行处理，offset 从 1 开始；单页内容上限为 256 KiB。超长行通过 `byte_offset` 继续读取。小文件无参数调用保留原字节输出。

Mistral 改用现有 OpenAI 兼容客户端，保持原端点和参数语义，原因是原 SDK 无法可靠传递取消且内含隐藏重试；本地 HTTP 测试覆盖了请求路径、工具和生成参数。

### 2.4 部署升级

部署前阅读 [DEPLOYMENT_SECURITY_MIGRATION.md](DEPLOYMENT_SECURITY_MIGRATION.md)。其中包括旧历史备份、两个新持久卷、用户批准、明确环境变量、自定义 MCP overlay、服务端/客户端 Key 对应关系及共享网络。

旧 UrlShortener 的管理认证、Go 附件客户端以及手机输入的 Key 必须对应。手机 Key 仅保存于本次运行的内存，不写入设置持久化或构建常量。可选短链 MCP 离线不会阻止首次启动；显式 `required: true` 仍按用户声明处理。

## 4. 明确限制与后续工作

1. **线上操作尚未执行。** 必须由部署维护者轮换暴露凭据、核对公网访问策略、构建并发布镜像。停止跟踪配置不能清除旧提交、镜像或备份中的值；本轮未重写 Git 历史。
2. **旧敏感历史仍物理保留。** 本轮屏蔽读取、分享和回滚中的敏感内容，未清洗旧 SQLite BLOB、WAL 或空闲页，也未自动销毁备份；优先轮换凭据并保护备份。
3. **多文件回滚不是断电原子事务。** 使用进程内预检和失败补偿；断电、进程终止和外部并发编辑仍可能需要人工恢复。补偿失败会报告并保留备份，不能宣称绝对不会部分应用。
4. **副作用与数据库之间没有 exactly-once 保证。** 文件或外部操作已完成但步骤完成状态未落库就崩溃，需要检查执行证据再恢复；仅靠 Plan CAS 不能推断外部操作是否完成。
5. **POSIX 清理边界有限。** 进程组能清理常规继承后代，无法保证清理主动 `setsid`/`setpgid` 脱离的进程；本地 shell 的 `Isolated` 仍为 false。Windows Job Object 与 POSIX 进程组的保证不能混为一谈。
6. **部分平台验证受限。** 本机 Windows `-race` 测试程序因 `0xc0000139` 无法启动，未获得竞态检测结论。普通 symlink 用例受创建权限限制；junction 已实跑。Linux 仅有交叉编译，仍需 Linux CI 执行进程、锁、链接和 race 测试。
7. **未调用真实外部依赖。** 模型使用假模型/httptest；MCP、存储、沙箱与数据库主要用本地 helper 或 fake。原有需要真实 Python 服务的集成测试按原开关跳过。
8. **架构后续仍在。** runtime/RAG 仍保存在原始 transcript 中，本轮只过滤请求中的旧动态内容；environment/plan 已改为请求注入。R-1 尚未完成 runtime/RAG 完全脱离持久化的状态传递。外层预压缩暂保留兼容入口，主 Agent Loop 使用完整 RequestBudget 重新压缩与校验。未完成全部原生协议重写、独立并行 Plan 子会话、微压缩、实际 token 用量校准、RAG 索引生命周期、后台 shell 体系、完整产物取回契约或全部 P2 改进。它们不应随本轮补丁被标记为已完成。
