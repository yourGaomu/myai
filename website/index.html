Plan 模式 · AutoPlan

先看 Agent 打算改哪里，再决定是否执行。也可以启用 AutoPlan，让规划和执行在一次请求里接续完成。

子智能体

把排查或补测试拆给子智能体，查看各自的运行进度和工具调用。使用隔离工作区时，可审阅子任务的改动，然后选择应用或丢弃。

权限审批

为工具设置询问、放行或拒绝策略。需要审批时，先在手机上看清命令，再决定是否允许本次调用。

工作区时光机

用基线对比查看每个文件具体改了哪些行。对可恢复的变更，可以只还原选中的文件。

rag

本地优先的知识库

把项目规范和内部文档放进知识库，按会话圈定 Agent 可以查阅的资料。既能按需手动检索，也能让 Agent 自动检索或每轮检索。

把运行中总结出的解决方案和经验留给下一次任务。你可以审核、编辑记忆，并限定它的使用范围。

MCP · Skills · Hooks · Plugins

用 MCP 接入自己的工具，用 Skills 沉淀操作流程。也可以通过 Hooks 和 Plugins 扩展 Agent 的运行方式。

五种模型协议

03 / 架构

三个进程，各司其职。

Relay 不是业务后端，它只负责配对、鉴权和转发。真正读写代码、调用模型、执行工具的，是跑在你电脑上的 PC Agent。

myai relay

只转发，不思考

每个 Agent Token 绑定到固定的 user / device。多台电脑各用各的凭据，不共享 Token。

myai agent

代码在你指定的工作区执行

文件读写和工具执行由 PC Agent 发起；使用远程模型时，推理所需的上下文会发送给所配置的模型服务。

core/

分层 + 六边形架构

应用层只依赖接口，Mongo、Redis、LLM、工具等适配器实现接口，由 composition 显式装配。

04 / 安全

放权给 AI，
但不失控。

让 Agent 真正动手，前提是每一步都看得见、拦得住、退得回。

  • 01

    六位码配对

    绑定码只用于换取客户端 Token，不直接作为 WebSocket 凭据。

  • 02

    身份绑定的 Relay

    Agent Token 与 user / device 一一对应。部署时仍需自行配置强随机凭据、网络边界和 HTTPS/TLS。

  • 03

    逐次审批

    需要审批的工具调用会等手机确认；拒绝时，该次工具调用不会运行。

  • 04

    路径与进程策略

    工作区边界与进程策略限制 Agent 能碰到的文件和命令。

  • 05

    可选沙箱

    集成 OpenSandbox，myai sandbox doctor 一条命令做冒烟测试。

  • 06

    按文件还原

    以已保存的工作区历史为基线，检查并还原可恢复的文件改动。

05 / 快速开始

从配置模型开始，
再连接你的设备。

STEP 01

准备 Go 与项目目录

需要安装 Go 1.25+。先克隆仓库，再按下一步安装模型配置。

# 从仓库根目录开始
git clone https://github.com/yourGaomu/myai.git
cd myai

# 确认 Go 版本
go version

# 下一步：安装模型配置
STEP 02

安装示例配置并填入模型

MyAI 默认读取 resource/application.yaml。示例文件里有默认模型名；按你实际使用的服务填写 provider、protocol、API 地址、密钥和模型名。

# Windows PowerShell · 在仓库根目录执行
New-Item -ItemType Directory -Force resource | Out-Null
Copy-Item config/application.example.yaml resource/application.yaml

# 用你熟悉的编辑器填写模型配置
notepad resource/application.yaml

模型配置完成后，在仓库根目录运行：

go run . chat

Relay 和 Agent 要分别运行。示例中的 replace-with-a-strong-token 请换成你自己生成的长随机 Token。

# 终端一：启动 Relay
go run . relay --addr 0.0.0.0:18080 `
  --agent-token "replace-with-a-strong-token" `
  --agent-user local --agent-device pc-local
# 终端二：启动 PC Agent（替换成实际工作区路径）
go run . agent --server ws://127.0.0.1:18080/ws/agent `
  --relay-token "replace-with-a-strong-token" `
  --user local --device pc-local `
  --workspace "D:\your\project"

提示 手机上的 Relay 地址需要手机可访问。绑定码由 Agent 启动时打印，Token 必须换成你生成的随机值。

从仓库根目录启动移动开发服务器，再在 Expo Go 或 Android 模拟器中打开项目。

cd mobile
npm ci
npm start

# Android 模拟器 Relay 地址：http://10.0.2.2:18080
# 真机请用 PC 的局域网 IP，例如 http://192.168.1.23:18080

提醒 MyAI 不会自动启动 Relay、注册模型服务或替你创建 API 密钥。手机与 PC Agent 也需使用相匹配的版本。

07 / 常见问题

你可能想问。

MyAI 和 IDE 里的代码补全工具有什么不同？

补全工具在你写代码时给建议；MyAI 是一个能独立完成任务的 Agent：它会规划、调用工具、修改文件和运行命令，按你的权限策略请求审批。加上 Relay 和手机端，你不坐在电脑前也能指挥它。

用手机控制电脑，安全吗？

Relay 只负责配对、鉴权与转发，Token 绑定到具体的 user / device；需要审批的工具调用会等你在手机上确认；工作区历史支持还原可恢复的文件。你也可以自建 Relay 并配置 TLS。

运行它需要哪些依赖？

本地对话需要 Go 1.25 或更新版本，以及一份可用的模型配置。手机控制还需要 Relay 和移动客户端；持久化和知识库所需的服务按部署配置启用。

支持哪些大模型？

支持 OpenAI Chat Completions、Anthropic Messages、Google Generative AI、Mistral Chat 与 Ollama Chat 五种协议及其流式响应，也可接入实现相应协议的服务，或通过 Ollama 使用本地模型。

手机端支持哪些平台？

客户端基于 Expo React Native，目前主要在 Android 与 Expo Web 上使用和验证。

我能给它加自己的工具吗？

可以。接入兼容的 MCP 服务，或在工作区 plugins/ 目录放置带 plugin.json 的插件（以 MCP stdio 进程运行）；也可以通过 myai skill 安装 Skills，用 Hooks 介入生命周期。
