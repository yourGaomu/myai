MyAI Mobile · UI Redesign

把「吵闹」收成「安静」

现状的根本问题不是配色，而是没有任何东西比别的东西重要。每一个元素都有 2px 黑边、 都有硬阴影、都是 800/900 字重，于是整屏的信息层次被抹平了。下面给三个方向，都能解决这个问题，但气质差别很大。

01

先说清楚问题在哪

我把 src/ 里所有颜色统计了一遍：#12100e（近黑）出现 475 次， #ffd84f（亮黄）70 次。几乎每一个容器都同时拥有 borderWidth: 2 和 shadowRadius: 0 的硬阴影。这不是"粗野主义风格"，这是没有决策——因为不敢丢掉任何东西，所以全都加了边。

01 · 层次
所有东西同样响
Header 一屏里塞了 3 个 40px 带边框圆按钮、1 个带边框浮岛、浮岛里还有头像 + 名字 + 设备徽章 + 状态胶囊 + 模式药丸，每个都有边框和阴影。发送按钮和菜单按钮长得一样重。
02 · 消息流
四种气泡四种底色
用户黄、助手米白、工具青蓝、错误珊瑚红，全部带边。滚动时看到的是一片色块， 而不是一段对话。助手回复应该是阅读的主角，现在它和工具卡片抢注意力。
03 · 主题
主题文件是死代码
constants/theme.ts 定义了深色 Zinc 系统（#09090b / #22c55e）， 但没有任何组件引用它。实际渲染的是一套写死在各个 StyleSheet 里的纸感配色。 而 app.json 又声明了 userInterfaceStyle: "dark"。
04 · 字号
没有级差
实际在用的字号是 9 / 10 / 10.5 / 11 / 12 / 13 / 13.5 / 14 —— 相邻差 0.5px，肉眼无法分辨， 构成不了层级。同时大量正文落在 11px 以下，手机上偏小。
05 · 导航
聊天时没有导航
BottomDock 是二选一：viewMode === "chat" 显示输入框， 否则显示 5 段标签。所以对话模式下文件/变更/知识只能从侧边抽屉进，多一次点击。
06 · 图标
Emoji 当图标
☰ 🕒 ⚙ 📎 ▶ ■ 🎯 💬 —— 每个 Android 厂商的 emoji 字体不同， 渲染出来粗细、大小、基线全不一致，观感廉价且不可控。
02

现状 · 复刻

按 AppHeader / MessageBubble / Composer / BottomTabs 的样式值 1:1 还原，方便对照。

C2 · 权限确认

漫画风在这里反而最能体现价值：危险操作配爆炸框 + 放射线，天然把"要小心"传达出去，比一个平静的灰底弹窗有效得多。

漫画风的真实代价，先说清楚： ① 你的对话里有大量代码、diff、表格——这些内容一旦套上 2.5px 描边和网点底纹就不可读了，所以必须分区对待： 外壳漫画化，正文保持中性。② 网点底纹和硬阴影在低端 Android 上有渲染成本，且 react-native-svg 做 clip-path 爆炸框是可行的（Polygon），但比纯 View + borderRadius 复杂。③ 这套风格的辨识度最高， 但对"专业工具"的观感有风险——用户可能会觉得它不够严肃。
06

Token 对照

三个方向共用同一套语义化 token 名称，只是取值不同。这意味着实现上只需要改一个 theme.ts，所有组件就已经能切换方向——这也是我建议先做的第一步。

关于 B 的工程注意：原型里用了 backdrop-filter，React Native 在 Android 上没有原生支持。 落地时用 expo-blur 的 BlurView（Android 上是半透明实色近似，视觉 90% 接近）， 或者直接退化成 rgba(28,28,34,.9) 实色 —— 差别很小，但省掉一个依赖。
